# kid-workbench 后台分工

改进度后台或孩子知识库前先读本文。这是产品切法，不是实现清单。

共用同一套 `study_workbench`、同一个孩子。两套后台主语都是「这个孩子」，不要做成两套换皮的总览。

## 进度后台（`parent-dashboard/`，http://localhost:19081）

侧重：**这段时间学会了什么。**

- 日、周、月都能看，也能翻历史，不是只看今天。
- 打开要能清楚看到：练了多少、新掌握了哪些知识。
- 识字矩阵和字详情留在这边，不要搬到知识库。
- 当天错了几题可以写在摘要里；不要在这里做错因、错选题、薄弱点清单。

主问题：这段时间学会了什么。  
时间是主滤镜。正向内容（新掌握、掌握地图）放这里。

## 孩子知识库（`diagnosis-admin/`，Vite http://localhost:19212 / Docker :19211）

侧重：**截至现在会了哪些能力、具体答错了什么、接下来复习什么。** 练过算积累，掌握状态与错题事实分别呈现。

完整思想见 [`diagnosis-admin/孩子知识库.md`](diagnosis-admin/孩子知识库.md)。

- 练过的知识点算积累，不管会不会。
- 打开能看到每项能力的当前状态、错题与具体错选；按知识点查看，不复制时间进度总览。
- 知识库只读学习表；复习建议交题目后台保存、校验并生成草稿，发布与真实作答分别追踪。
- 不要再做第二份日/周/月日历，不要再铺一张识字绿格子。

主问题：账本里有什么、漏在哪。  
日期只作为错题发生时间，不是主界面。

## 素材后台（`content-admin/`，http://localhost:19091）

编题、配图、配音、审核发布。主语是「这门课的内容」，不是这个孩子。不要叫「知识库」。

## 题目后台（`task-admin/`，http://localhost:19201）

按任务使用素材后台内容生成题目，管理题包预览与发布；复习也是一种出题任务。可以读取作答事实生成复习题，不负责孩子进度、学习情况展示或掌握度更新。目录和接口保留 task-admin / question-tasks。

## 不要混的三对词

| 说法 | 归进度 | 归孩子知识库 |
| --- | --- | --- |
| 学会了 vs 积累了 | 变成已掌握，以及哪一天学会的 | 练过就算进库存 |
| 作答记录 | 按天看这一天答了哪些 | 按知识点看这个字/词错过什么 |
| 正确率 | 日/周/月汇总 | 某个知识点、某种题型 |

## 改代码时

- 往进度后台加「需要关注 / 错因 / 最近错选」之前，先问是不是该进知识库。
- 往知识库加「今日分钟数 / 本周趋势 / 识字矩阵」之前，先问是不是该进进度。
- 现有诊断台页面是知识库的种子，改名和减重时以 `孩子知识库.md` 为准，不要再做成第二份进度总览。

## 开发完成后的部署

- 沿用服务原有端口，通过新镜像替换对应的旧容器，验证正常后删除该服务已替换的旧镜像。
- 只构建和更新本次修改的服务（Compose 使用指定服务及 `--no-deps`），不要重启整套服务或数据库，不删除数据卷。
- 不用额外端口作为最终交付；开发时启动的临时预览服务，交付前关闭。

## 四端按菜单统一的协作记录

用户已授权从识字第一题型开始推进。修改相关题面前阅读 [按菜单推进方案](docs/menu-alignment/按菜单推进方案.md) 和 [识字执行档案](docs/menu-alignment/01-识字.md)。App 定题型与效果，素材定内容，题目后台负责生成，进度浏览保留原题且只读。每次修改把用户要求、各端改法、验证与待办写回菜单档案。当前完成范围以档案为准；未完成菜单不能因共用组件存在而视为完成。

跨菜单交接先读 [当前有效题面约定](docs/menu-alignment/当前有效题面约定.md)，拼音实施接续 [拼音执行档案](docs/menu-alignment/02-拼音.md)。历史日志保留旧方案，实施以当前有效约定及用户最新决定为准；识字图片题参数不能不经适配直接套用全部拼音题型。

最新五端范围：用户已将孩子知识库纳入按菜单改造，App 与四个后台须逐端交付；执行先读 [五端菜单实施标准](docs/menu-alignment/03-五端菜单实施标准.md)。历史档案里的范围排除项以本标准的最新授权为准，不得以 App 取题暂缓为由跳过题目后台生成与预览。

按菜单交付还必须准备可复核的验收数据，英语及后续菜单先读 [菜单验收数据标准](docs/menu-alignment/05-菜单验收数据标准.md)：每个实际详情至少 3 道题包实例、独立演示孩子的正确/错误/具体选择快照与媒体验证，禁止空态交付或污染真实孩子账本。
