# 识字素材加载失败修复

症状：素材目录部分请求 500，整页提示加载失败；媒体代理也返回 500。

原因一：识字服务加入两个网络，两边都有 postgres 别名。连接池实际同时连接本项目库和共享网络的旧库，旧库缺少 literacy_assets 和 study_plans.subject_code。Compose 为 literacy-server 单独设置 APP_DB_HOST=kid-workbench-postgres-1，替换该服务容器以清除错误连接池。未修改数据库。

原因二：上轮 Nginx 动态素材代理的 set 放在 rewrite ... break 后，变量未赋值。将 set 前移，保留路径转换与运行时 DNS。仅重建 App 镜像，在原端口使用 --no-deps 更新。

验证：App 19152 原端口并发查询全部 30 组、300 个字成功；山水日木的字图、义图、读音共 12 项返回 200，内容类型正确；首页接口成功。浏览器看字选义的五张图片全部加载，错误提示消失。首页与题型布局未改。

后续验收必须检查目录、图片与音频，不能只检查首页 HTTP 200 和容器状态。其他双网络服务也可能存在同名数据库风险，本轮仅修复已确认出错的识字服务。
