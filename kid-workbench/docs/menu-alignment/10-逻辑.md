**不要把本档案、测试通过或造数成功写成用户验收通过。**

本菜单是独立的 `logic` / 逻辑小站，不是识字或英语。

## 用户要求及不可改变项

- App + 素材后台 + 题目后台 + 进度后台 + 孩子知识库五端同时交付。不得遗漏题目后台或孩子知识库。
- 对照标准是 **logic-app 当前路由真正展示的 6 个首页入口**：pattern / classify / order / shape_reason / diff / compare。路由 `/practice/type/:type/:n?` 与 `/practice/type/:type/result`。
- classify 当前实际交互是「点出不属于该类的一个」，不是拖拽分组。本轮保留单选排除。
- App 本阶段允许固定示例与 live generate；已有 generate 链路不退回硬编码。固定示例必须能由素材和题目后台完整表达。
- 同题型五端共用 `packages/logic-player` 与 `shared-go/logiccontent`。后台外壳沿用各宿主识字菜单风格。
- 不改 App 首页六张黏土卡。题干、规律序列、选项、排序槽的位置和比例以逻辑 App 实际效果为准：左题干约 0.62、右四宫格铺满，断点 `max-width:760px` 才上下堆。不要套识字/英语 800/900。
- 不依赖系统 Emoji 表现关键差异。图形用版本化 SVG（当前 `glyphVersion=2`：箭头尖朝右，rotate 0=向右、90=向下）。历史只读冻结字节；源图更新后旧题不变。
- 所有题目保存可解释规则，不能只存 `answerIndex`。
- 素材页只读：搜索、筛选、展开、看图、详情。禁止生成/重做、编辑保存、导入、启停、审核发布、删除。
- 题目后台从真实逻辑素材及明确规则生成并保存六类题。精简任务卡片；查看弹窗关闭/Esc/焦点恢复。预览可本地试答，不写账本。
- 进度按日/周/月/历史看练习与新掌握；详情看当时原题。不把答对一道当成整个入口掌握。`SkillsFor("logic")=nil`，按知识点单行掌握；入账用 `SkillIsTracked`。
- 知识库按知识点展示积累、掌握、错误及具体作答（选了哪个对象，或排出的顺序与被拒绝的误点）。
- 历史媒体表 **`logic_question_task_media`**。live `/api/v1/logic/items/{kpId}/glyph/{objectId}.svg`；冻结 `/api/v1/logic/task-media/{sha256}.svg`。进度代理 `/api/logic/task-media/`，知识库 `logic:` 前缀，均打到 **logic-server**。
- 验收孩子名称必须包含「逻辑验收演示（非真实记录）」。每实际详情至少 3 道已保存题。脚本 `scripts/verify-logic-alignment.py`，证据 `docs/verification/logic-alignment/`。

## 覆盖矩阵（首页入口 → 实际详情 → 交互 → 素材 → 生成器 → 历史）

| 首页入口 | 路由 | 交互 | 素材字段 | 生成器 | 历史还原 |
| --- | --- | --- | --- | --- | --- |
| 找规律 | `/practice/type/pattern` | 点选下一元素 | rule.type/period/dimension、sequence[]、options 稳定 ID、answerId | `pattern` | 当时 optionOrder + selectedId |
| 分类 | `/practice/type/classify` | 单选排除 | rule.dimension + inGroup、对象 attrs.category，唯一不属于 | `classify` | 当时选项顺序 + selectedId |
| 排序 | `/practice/type/order` | 点右侧块填左侧编号槽；错点即时拒绝 | 元素稳定 ID、correctSequence、displayOrder、dimension/direction | `order` | 完整 sequence + rejected 误点 |
| 图形推理 | `/practice/type/shape_reason` | 点选下一图形 | 变化维度 shape/color/count/direction，序列结构 | `shape_reason` | 当时选项 + selectedId |
| 找不同 | `/practice/type/diff` | 单选唯一异常项 | 比较维度，有且仅有一个异常 | `diff` | 当时选项 + selectedId |
| 比较 | `/practice/type/compare` | 点选最大/最高/最快等 | 属性、方向、visualScale；画面尺寸题必须 scale 体现 | `compare` | 当时选项 + selectedId |

classify / diff / compare 都是选择题交互，规则不同，不能互相冒充覆盖。

## 发现并修复的歧义题

| 旧样例 | 问题 | 处理 |
| --- | --- | --- |
| 找不同「四种不同水果指定梨」 | 无唯一比较维度 | 验收素材改为三蓝一红（颜色）等唯一异常项 |
| 找不同「四个不同方向指定左」 | 四项全不同 | 改为三个向右、一个向左 |
| 比较仅靠系统 emoji 同字号 | 无法用眼睛比较 | SVG + `scale` 1–4；公交车明显大于溜冰鞋 |
| 排序用 glyph 字符串当 ID | 相同图形无法区分 | 稳定 `id`；相同 glyph 仍分实例 |
| 出题器只写 answerIndex | 无法解释规则 | payload 保存 rule + 对象属性；生成器校验唯一答案 |
| 箭头 polygon 尖在左侧 | 标签「向右」与画面相反；序列右→下→左被画成左→上→右 | 尖改到 +x；`glyphVersion=2`。已冻结 `glyphVersion=1` 字节不改写 |

## 结构化输入

| 交互 | 保存 | 判定 |
| --- | --- | --- |
| 选择类 | selectedId + optionOrder | selectedId == answerId |
| 排序 | sequence[] + rejected[{id,atIndex}] | sequence 与 correctSequence 全等；误点另记 |

未作答快照不得把空 `{"kind":…}` 写入 `selected`。
