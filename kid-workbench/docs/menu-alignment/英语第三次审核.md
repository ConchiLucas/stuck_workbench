1. `shared-go/englishcontent/snapshot.go` 中 `SnapshotFromLiveQuestion` 将图片保存为 `/api/v1/english/words/{id}/sense.png`，音频保存为 `/api/v1/english/words/{id}/speech.mp3`；`MediaSHA256` 的值实际取自 AssetKeys，属于地址/对象键，并非文件字节摘要。
2. `english-server/internal/asset/service.go` 继续按 `SenseKey(kpID)` / `SpeechKey(kpID)` 取对象。`keys.go` 对应固定路径 `english/senses/{id}.png`、`english/speech/{id}.mp3`。素材对象一旦替换，历史 GET 也会读取替换后的内容。保存 JSON 地址不变不等于保存了历史媒体。

4. `scripts/verify-english-second-audit.py:268` 起只修改源表字段、比较 JSON/字段值，没有替换实际存储对象并重新读取历史媒体比较字节。并且 `after_snap` 是重新解析更新前的 `snap_text`，比较其中摘要不能证明媒体冻结。修复报告第 5、8 节已坦诚注明这一限制，但它仍属于本轮原有验收要求。

### 下一轮必须达到的结果

- 保存历史题面时冻结实际图片/音频文件，使用不可覆盖的版本对象或按真实 SHA-256 寻址的媒体，进度和知识库均读取该冻结对象。可以复用现有任务媒体机制，不要求提前接入 App 从任务后台取题。

- 媒体未冻结、缺失或校验失败的旧记录如实标记，不以当前文件倒填历史后声称恢复成功。

- 验收报告分开记录题面 JSON、当次输入、媒体实际字节三个维度，不把局部通过写成完整历史不可变。
