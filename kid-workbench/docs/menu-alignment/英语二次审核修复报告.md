## 1. 问题与根因

### EN-A04：正常作答无法还原当次历史

1. `english-server` 创建计划时 `question_snapshot` 只有 `{code,type}`。进度/知识库解码要求 `schema=1` + 完整 `example`，因此 `attempts.plan_item_id` 只解决了“找最新计划串题”，没有让生产快照可渲染。
2. 同一 `plan_item` 的 `picks` 被写成累积 JSON 数组（列实际是 `VARCHAR(24)`）。进度/知识库把整份 picks 当 selected，未按当次 attempt 提取选择，也未把展示索引映射成稳定选项 ID。
3. 验收样例被造数脚本写坏：attempt 174 时间早于 149；脚本直接 `UPDATE question_snapshot`，把音频改成 64 个 `f`（HTTP 404），并把标签改成「苹果（更新后）」。这不能证明素材源更新后历史不变。

### EN-A06：完成率冒充正确率，题型数字写死

1. `ledgerFacts.ts` 用 `done_count / target_count` 填正确率。10 题完成但错 2 题仍显示 100%。
2. `Overview.tsx` 的 `SUBJECT_QUESTION_TYPES` 写死掌握/学习数；英语仍是旧三题型（含「单词认读」）。

## 6. 统计口径（本轮实际实现）

- **正确率** = `correct_count / done_count`（答对 / 已作答）。
- **完成率** = `done_count / target_count`，页面不再把它叫正确率。
- 条形分母是该学科题量：答对 / 答错 / **未作答**。
- 多学科计划按 `subjects[].done_count` / `correct_count` 拆。
- **同题当场重试**：任务/总览按 `plan_items.status` 只计最终结果；attempt 196 仍只读显示错选熊。
- 英语题型名来自 `mastery.SkillDisplayName`：听音选词、看图选词、组句子、写单词、读一读。

页面对照：

- 计划 186 API：**80%**。任务列表加餐1 显示 10/10 与 80%。
- 总览 9/13 英语 **87%**：孩子 5 当天还有脚本失败残留的其他计划，合计不是 80%。**不要把总览 87% 说成 10 题 80% 已在总览单独展示。**
