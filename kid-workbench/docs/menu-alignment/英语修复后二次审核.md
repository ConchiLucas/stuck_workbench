## 未通过项

### EN-A04 / P1：正常作答的历史快照生产与读取仍不兼容

- `english-server/internal/plan/service.go:92` 创建计划时，`question_snapshot` 仍只有 `code/type`，题干等字段另外保存在 plan_items 列中。
- `shared-go/englishcontent/types.go:118` 的历史解码要求 `schema=1`、有效 `kind`、完整 `example`。知识库 `internal/knowledge/english.go:31` 直接使用此解码器。因此新增 `attempts.plan_item_id` 虽然解决了“找最新计划串题”，并没有让正常计划生成的快照满足历史读取协议。
- `english-server/internal/practice/service.go:140` 把同一题各次作答累加到可变的 `pi.picks` JSON 数组。进度、知识库都读取整份 `pi.picks`；当前转换函数把它直接当作 selected 字符串，未按当次 attempt/client_id 提取选择，更未转换当次选项顺序中的稳定 ID。同题先错再对仍缺少正确的逐次还原。
- 修复要求：正常生产路径保存完整历史快照；每次作答保存或关联不可变的实际输入，明确索引与稳定 ID 转换。用独立演示孩子通过真实计划/作答接口验证同一 plan_item 先错再对，分别读取两条历史；不得仅手工插入两个完整快照证明正常流程通过。这不要求提前对接 App 从任务后台取题。

### EN-A04 / P1：历史验收样例本身被写坏

- 新演示孩子 4，attempt 149 时间 `2026-09-13T15:30:28.196847Z`；声称是后续作答的 174 却是 `2026-09-13T15:05:28.196847Z`，早了 25 分钟。
- `scripts/seed-english-audit-fix.py:366` 起直接修改第二条历史快照，把音频设为 64 个 f 的不存在地址，并把选项标签改成“苹果（更新后）”。这不是修改素材源后验证旧快照不变。
- 本轮实际 GET：149 的 stem-audio 为 HTTP 200、14976 字节；174 的 stem-audio 为 HTTP 404。174 仍报告 `mediaFidelity=immutable` 且未列出媒体异常，不能把该样例计入可完整还原的合格数据。
- 修复要求：补齐正常且时间顺序正确的重复作答样例，媒体可播放且图文一致。更新实际素材源，再检查两次已保存历史均不变。失效媒体测试如需保留，应单独标记为异常样例，不混入合格数据；不要直接篡改历史快照来模拟素材更新。

### EN-A06 / P1：进度页仍存在错误统计及写死数据

- `parent-dashboard/frontend/src/lib/ledgerFacts.ts:34` 以 `done_count / target_count` 填充 `correctPct`，这是完成率，不能称为正确率。例：10 题做完但错 2 题，该函数仍显示正确率 100%。应从真实作答事实计算，并明确未作答与错误的不同含义；多学科计划需要正确的学科分母。
- `parent-dashboard/frontend/src/pages/Overview.tsx:24` 的 `SUBJECT_QUESTION_TYPES` 仍固定填写掌握/学习数字；英语仍是 62/22、54/26、48/24，且只有三种旧题型。该常量在正式页面第 431 行附近渲染，并非仅未挂载示例。
- 修复要求：接入真实统计；无数据显示空/0，读取失败明确提示。不要把静态演示数字作为孩子掌握情况。增加“全部完成但有错题”和“无记录孩子”的验证。
