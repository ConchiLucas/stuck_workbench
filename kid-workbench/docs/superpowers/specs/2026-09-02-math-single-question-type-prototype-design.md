# 算数单题型前端原型设计

## 目标

把算数孩子端首页从模块进度和长期题型规划，收敛为一个可以完整体验的题型入口。第一版只展示“20 以内加法 · 看算式选答案”，让用户走通“首页题型卡 → 题型详情 → 模拟答题 → 模拟结果”。

本原型只使用前端静态数据，不调用后端创建计划、提交作答、更新掌握度或获取音频。现有 `math-server` 和正式练习页面保持不变。

## 首页

首页保留孩子名称和花朵数量，主体改为“题型练习”。移除以下可见内容：

- 今日混合练习卡及开始、继续入口。
- 406 种题型地图入口。
- 加法、减法、图形三张模块进度卡。
- 待复习提示。

首页只展示一张题型卡：

- 标题：`20 以内加法`
- 题型：`看算式选答案`
- 说明：观察加法算式，从四个数字中选出正确答案。
- 信息：5 道模拟题、四选一、答错可重试一次。
- 操作：点击整张卡进入题型详情。

视觉继续使用现有方格练习纸、深蓝墨水和绿色加法色，不建立新的设计语言。

## 题型详情页

路由为：

```text
/types/addition-equation
```

详情页包含：

1. 题型名称和“前端原型”标记。
2. 学习目标：理解两个数合起来的数量关系，并熟练计算 20 以内加法。
3. 作答规则：阅读算式，从四个候选数字中选择正确答案。
4. 一道不可提交的示例题，展示算式和正确选项的视觉形式。
5. 本次练习说明：共 5 题，第一次答错可以再选一次。
6. “开始答题”按钮。

详情页不显示音频按钮，也不声称已经保存学习进度。

## 模拟答题页

路由为：

```text
/types/addition-equation/practice
```

静态题目固定为五道 20 以内加法，每题包含题干、两个加数、四个不重复选项和正确选项下标。选项顺序在本次原型中保持固定，方便测试和评审。

交互规则：

- 一题一屏，显示当前题号和总题数。
- 点击选项后立即判断。
- 第一次答错显示“再想一想，你还有一次机会”，保留当前题。
- 第二次答错显示正确答案，然后允许进入下一题。
- 第一次答对直接允许进入下一题。
- 最后一题结束后进入模拟结果页。
- 刷新答题页会重新开始，不做本地持久化。

本页复用现有算式视觉风格，但使用独立的前端状态，不创建伪造的后端计划 ID。

## 模拟结果页

路由为：

```text
/types/addition-equation/result
```

结果页展示本次答对题数和总题数，提供：

- “再练一次”：清空前端练习状态并返回第一题。
- “回到题型详情”：返回题型说明页。

结果状态只存在于当前前端会话。直接访问结果路由但没有完成记录时，页面引导用户先开始答题。

## 前端结构

题型定义与题目数据放在独立文件中，页面不直接内嵌题库：

```text
math-app/src/content/questionTypePrototype.ts
math-app/src/pages/QuestionTypeDetailPage.tsx
math-app/src/pages/QuestionTypePracticePage.tsx
math-app/src/pages/QuestionTypeResultPage.tsx
math-app/src/store/questionTypePracticeStore.ts
```

删除上一版仅用于 406 题型目录的页面、测试和目录数据。首页不再链接 `/types` 总览路由。

## 后端接入边界

本次不修改 `math-server`，也不扩展组卷请求。未来正式接入时：

1. 后端创建计划请求增加受控的题型代码过滤。
2. 服务端验证模块与题型组合，并只选择匹配题目。
3. 详情页从内容接口读取题型信息。
4. 答题页切换为正式计划快照、TTS 和幂等提交。
5. 删除前端静态练习状态，不同时维护两套正式作答逻辑。

## 错误与空状态

- 静态题库随应用构建发布，不设计“数据缺失”分支。
- 未完成练习而直接进入结果页时，不显示虚构成绩。
- 原型没有网络请求，因此不增加后端错误提示或离线兜底。

## 测试

- 首页只出现一张题型卡，并能进入详情页。
- 详情页展示题型目标、示例和开始按钮。
- 答题页覆盖首次答对、首次答错重试、二次答错和完成跳转。
- 结果页覆盖有成绩和无成绩两种访问方式。
- 删除的 406 题型地图不再有路由或首页入口。
- 完整 Vitest 测试与 Vite 生产构建通过。
