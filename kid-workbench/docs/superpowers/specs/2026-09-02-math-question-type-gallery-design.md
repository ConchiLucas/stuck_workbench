# 算数题型卡片画廊设计

## 目标

把算数孩子端首页从单张大型原型卡改为题型画廊，让用户一眼看到加法、减法和图形分别有哪些题型。页面以展示为主，不要求所有题型立即具备答题能力。

## 页面结构

首页保留标题和孩子信息，下方按三个内容模块分组：

1. 20 以内加法
2. 20 以内减法
3. 认识图形

每组包含四张题型卡。桌面端每行四张，窄屏改为两张，手机端改为一张。

不恢复 406 种题型地图、学习进度卡、每日练习卡或待复习提示。

## 题型清单

### 20 以内加法

| 编号 | 题型 | 状态 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| 01 | 看算式选答案 | 当前支持 | 观察加法算式，从四个数字中选择和 | `3 + 5 = 8` |
| 02 | 看数量图选答案 | 当前支持 | 观察两组物品合起来的数量 | `3 个 + 2 个 = 5 个` |
| 03 | 补全算式 | 可以扩展 | 补上缺少的加数或结果 | `3 + □ = 8` |
| 04 | 判断算式对错 | 可以扩展 | 判断给出的加法算式是否成立 | `7 + 6 = 12 ?` |

### 20 以内减法

| 编号 | 题型 | 状态 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| 01 | 看算式选答案 | 当前支持 | 观察减法算式，从四个数字中选择差 | `9 - 4 = 5` |
| 02 | 看数量图选答案 | 当前支持 | 观察物品拿走前后的剩余数量 | `8 个拿走 3 个` |
| 03 | 补全算式 | 可以扩展 | 补上减数、被减数或结果 | `12 - □ = 7` |
| 04 | 找出错误算式 | 可以扩展 | 从若干算式中找出计算错误的一项 | `14 - 6 = 9` |

### 认识图形

| 编号 | 题型 | 状态 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| 01 | 听名称找图形 | 当前支持 | 听到图形名称后选择对应图形 | `听“圆形” → ○` |
| 02 | 看图选名称 | 当前支持 | 观察图形后选择正确名称 | `△ → 三角形` |
| 03 | 按特征找图形 | 可以扩展 | 根据边、角或曲线特征选择图形 | `找出没有角的图形` |
| 04 | 图形分类 | 可以扩展 | 按指定规则把多个图形分组 | `把图形分成两组` |

## 卡片设计

每张卡包含：

- 两位编号。
- “当前支持”或“可以扩展”状态标签。
- 与题型含义对应的图形或算式符号。
- 题型名称。
- 一句孩子和家长都能理解的说明。
- 一条具体示例。

三组使用现有学科颜色区分：加法使用绿色，减法使用珊瑚红，图形使用紫色。卡片保持白底、深蓝描边和方格纸背景，结构参考用户提供的拼音题型卡，但不复制其颜色和图标。

卡片以紧凑、可比较为目标，移除现有大型卡片中占据半屏的算式区域。

## 交互边界

- “20 以内加法 · 看算式选答案”保持可点击，进入已经实现的详情和五题模拟答题。
- 其余十一张卡只展示，不添加失效按钮、空白详情页或“敬请期待”弹窗。
- 可点击卡使用真实链接和箭头；只展示卡不使用链接或按钮，避免造成虚假可操作性。
- 状态标签表示内容系统的当前能力，不表示用户掌握度。

## 数据结构

在前端静态内容模块中新增统一 `QuestionTypeCard` 定义：

```ts
interface QuestionTypeCard {
  id: string
  module: 'addition' | 'subtraction' | 'shape'
  order: number
  title: string
  description: string
  example: string
  mark: string
  status: 'supported' | 'expandable'
  href?: string
}
```

首页只负责按模块读取和展示卡片，不把十二张卡逐张硬编码到 JSX。现有五道模拟题继续放在同一静态内容域中。

## 测试与验收

- 首页准确显示三个分组和十二张题型卡。
- 每组四张，顺序与设计清单一致。
- 六张标记“当前支持”，六张标记“可以扩展”。
- 页面只有一张卡具有链接，目标为 `/types/addition-equation`。
- 首页不出现 406 题型地图、每日练习和模块掌握进度。
- 现有题型详情、模拟答题与结果页测试保持通过。
- 桌面端、两列窄屏和单列手机端均无溢出。
