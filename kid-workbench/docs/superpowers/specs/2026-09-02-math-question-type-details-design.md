# 算数十二种题型详情页设计

## 背景与目标

算数首页已经按“20 以内加法、20 以内减法、认识图形”展示十二种题型，但目前只有“20 以内加法 · 看算式选答案”可以进入详情。此次改动让十二张卡片都能进入各自的题型详情，帮助用户理解每种题练什么、如何作答以及题目长什么样。

本阶段只补齐详情展示。除现有“20 以内加法 · 看算式选答案”外，其余十一种题型不实现答题、计分或结果流程，也不接入后端。

## 方案

采用数据驱动的统一详情页。

- 十二种题型共用 `/types/:typeId` 路由和一个详情页组件。
- 每种题型通过静态配置提供所属模块、名称、状态、学习目标、三条作答步骤和例题描述。
- 详情页根据例题种类渲染算式、数量、判断、图形或分类等不同预览，而不是为十二种题型复制页面组件。
- 现有 `addition-equation` 的五题答题流程和 `/types/addition-equation/practice`、`/result` 路由保持不变。

## 页面与交互

### 首页卡片

十二张题型卡全部变为链接，地址为 `/types/<题型 ID>`。卡片继续保留“当前支持”或“可以扩展”标签；该标签描述题型在既有系统中的支持程度，不代表本阶段已经实现对应答题流程。

### 通用详情页

每个详情页包含：

1. 返回首页入口。
2. 所属模块、题型名称和支持状态。
3. “这种题练什么”：一句明确的学习目标。
4. “怎么作答”：三条顺序清晰的步骤。
5. “例题”：使用符合题型特点的可视化预览。
6. 底部动作区域。

`addition-equation` 底部继续显示“开始答题”，点击后初始化现有五题练习并进入答题页。其余十一种题型显示“当前先展示题型说明，练习内容后续接入”，并提供“返回题型首页”按钮，不显示不可用的答题按钮。

### 例题类型

- 看算式选答案：算式和四个数字选项，标出正确答案。
- 看数量图选答案：两组或拿走后的物品符号，加上数字选项。
- 补全算式：突出空格，并展示候选数字。
- 判断或找错：展示算式以及对错判断或错误项。
- 听名称找图形：以“播放名称”的静态视觉提示配合图形选项；本阶段不新增音频逻辑。
- 看图选名称：展示目标图形和名称选项。
- 按特征找图形：展示特征提示和多个图形候选。
- 图形分类：展示两组分类容器及图形分布。

所有例题只承担详情说明作用，不可点击作答，也不维护答题状态。

## 数据结构

在现有题型静态内容模块中扩展详情元数据：

- `learningGoal`：学习目标。
- `rules`：固定三条作答步骤。
- `example`：带 `kind` 判别字段的例题数据。
- `practiceHref`：仅 `addition-equation` 配置。

首页卡片和详情配置使用同一个题型 ID。提供按 ID 查询详情的函数，避免页面直接遍历并自行判断。

例题使用判别联合类型，详情页把每种例题表现拆成小型渲染组件。各组件只负责展示，不依赖路由或练习状态。

## 路由与异常处理

- 通用详情路由：`/types/:typeId`。
- 现有练习和结果路由保持具体路径，不改为动态路由。
- 当 `typeId` 不存在时，详情页显示“没有找到这个题型”，并提供返回首页入口；不抛出运行时错误。
- 静态详情数据完整存在，因此不增加加载态、缺失字段兜底或后端请求。

## 视觉与响应式

详情页沿用当前方格练习册风格和双栏布局。左栏统一展示目标和步骤，右栏根据例题种类变化。模块色延续首页：加法绿色、减法珊瑚色、图形紫色。

桌面端保持双栏；窄屏改为单栏，例题置于说明之前。图形、选项和分类容器不得产生横向滚动。所有真实链接保持键盘焦点样式和至少 56 像素的可点击高度。

## 测试与验收

- 数据测试：十二种题型均有完整详情、唯一 ID、三条规则，只有 `addition-equation` 有练习地址。
- 首页测试：十二张卡片全部为链接，链接与题型 ID 一致。
- 路由测试：任取加法、减法、图形各一种，均能显示对应名称、目标、规则和例题。
- 兼容测试：现有加法详情仍可进入五题答题页。
- 异常测试：无效题型 ID 显示未找到页面。
- 完整验证：全部 Vitest 测试、TypeScript/Vite 构建通过，并在桌面及 390 像素宽度浏览器检查首页和三类详情。

## 明确不做

- 不为另外十一种题型生成题库。
- 不为静态例题增加可点击反馈、计分或结果页。
- 不调用算数后端，也不修改后端协议。
- 不修改已有五题练习的题目、状态管理和结算逻辑。
