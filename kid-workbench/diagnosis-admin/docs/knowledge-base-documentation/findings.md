# 已核对的上下文

- 用户最新定位：直观看会了哪些能力、错了哪些题，分析后向题目后台提供复习计划。
- 底层必须读取全部真实作答，错题是其中的分析入口；掌握仍由 shared-go 与学科学习服务决定。
- diagnosis-admin 当前四个 GET 接口、四页，数据库只读；新接口应独立命名，保留旧链接兼容。
- 当前错误归纳会把单次错选称为反复错选、未练技能称为弱；技能详情未传 moduleCode，影响拼音音节和算数。
- 识字新题回执包含稳定选项 ID、书写笔迹和评估；拼音有独立实例和回执；应以 attempts.id 为事实去重基准。
- 当前 task-admin 存在识字和算术普通出题；复习服务仍限单个已完成的识字计划。
- task-admin 的 review-evidence 接口已经可以还原选项、书写 payload 与评估，当前无分页。
- 原文档禁止知识库写掌握度、生成题包；新建议可由知识库提交，但业务记录存于 task-admin，由它生成草稿和发布。
- 本轮只读检查代码，没有查询真实学习数据库或测试运行中服务。
- 科普 completed 计划项不能用来排除错误；attempts 是对错唯一计数来源。
- parent_mark 是人工标记，不能作为孩子真实答题；提示状态需依赖具体来源契约，不能从缺字段推定独立。
- 009 迁移回填快照不能保证原作答画面；旧选项顺序需 option_order 映射且精确关联。
- 当前 PreviewReview 的 mixed 分支会冻结素材，候选分析 GET 不得复用它。
- 方案确定：先保存建议，再显式生成草稿，在题目后台发布。建议数据归 task-admin；首版保持来源计划已完成约束。
- 自查统一 SourceRef 字段；知识点能力筛选分页使用状态摘要检测变化；建议、生成、题包、效果四种状态独立。
