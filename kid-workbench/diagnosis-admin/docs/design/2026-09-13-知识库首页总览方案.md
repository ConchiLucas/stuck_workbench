# 孩子知识库：首页总览布局方案 V2

状态：2026-09-13 已按用户批准的 V2 实施并部署至原端口 http://localhost:19211。下文保留设计依据；正式页面已实现菜单下钻，使用真实数据。

## 本轮方向

用户希望像进度后台首页一样，以图为主、文字极少；首页先形成整体印象，具体内容通过菜单查看。

首页只回答三个问题：**能力是什么状态、错误集中在哪、复习安排到哪一步。** 不放具体题目、错因列表、建议明细和长说明。

## 推荐布局

```text
┌──────────┬──────────────────────────────────────────────────────┐
│ 孩子知识库│ 知识总览                         孩子 / 已练知识点数   │
│          ├──────────────────────────────────────────────────────┤
│ 总览     │  学科图标  学科图标  学科图标  …… 共 9 项              │
│ 能力档案 │    数字      数字      数字       （各科已练知识点数）    │
│ 错题记录 ├──────────────────────────────┬───────────────────────┤
│ 复习建议 │ 各科能力状态                  │ 错题分布              │
│          │                              │                       │
│          │ 学科  ▰▰▰▰▰▰▰▰▱▱             │ 学科  ▰▰▰▰▰  数字     │
│          │ 学科  ▰▰▰▰▰▰▱▱▱▱             │ 学科  ▰▰▰    数字     │
│          │ 学科  ▰▰▰▰▰▰▰▱▱▱             ├───────────────────────┤
│          │ ……                           │ 复习状态              │
│          │                              │                       │
│          │ ● 已掌握 ● 练习中             │  ▰     ▰     ▰     ▰  │
│          │ ● 待巩固 ● 尚未练             │ 待生成 草稿 待作答 有作答│
└──────────┴──────────────────────────────┴───────────────────────┘
```

桌面主体约 3:2：左侧一张大图，右侧两张小图。目标为常见桌面一屏看完整体，减少纵向堆叠。窄屏按学科入口、能力状态、错题分布、复习状态顺序排列。

## 首页内容

| 区域 | 展示 | 进入详情 |
| --- | --- | --- |
| 顶栏 | 标题、孩子身份、少量数字摘要；不加解释段落 | 无额外详情区 |
| 学科一排 | 沿用现有九学科名称和图标，每项一个已练知识点数 | 点击进入该学科能力档案 |
| 各科能力状态 | 每学科一行堆叠横条，四种状态共用图例 | 点击进入该学科能力档案 |
| 错题分布 | 各学科历史错误次数的横向条形图 | 点击进入对应学科错题记录 |
| 复习状态 | 已保存建议按待生成、草稿、待作答、有作答展示四个并列数量小图 | 点击进入对应复习建议列表 |

图中保留学科名、状态名和必要数字。具体值可通过悬停或触摸查看；不要求阅读文字才能看懂页面。首页不嵌入题目卡片、知识点例字、具体错选、错误原因、复习理由或最近建议列表。

## 图形与数据口径

- **能力图**：统计单元为“知识点 × 该知识点适用的能力”。范围为已经练过的知识点及其适用能力，四种状态互斥。尚未练表示该能力没有练习证据，不表示薄弱；不将不适用的能力补成尚未练。
- **能力比例**：每科横条展示四种状态占比，悬停显示数量与分母。各科适用能力不同，不用比例进行成绩排名。
- **数量命名**：学科入口的“已练”按知识点去重；能力图按能力单元计数。顶栏若使用现有按知识点去重的掌握数，必须叫“有掌握能力的知识点”，不能叫“已掌握能力数”。空间不足时删去该摘要，不缩短成误导性标题。
- **错误图**：统计有明确错误结果的作答事实次数，以作答记录去重；保留历史错误，后来答对不抹去。图题或短单位标识为“历史错误次数”，不表达当前不会，也不计算错误率。
- **复习图**：四阶段必须使用同一统计单元，并在正式开发前定义互斥归类规则及混合状态的处理。不能把候选知识点数、建议份数、题包数和作答次数混成一张图。仅画并列状态数量，不画转换漏斗、不用连接箭头暗示转化；“有作答”不等于已掌握，也不证明建议带来提升。
- **数据来源**：能力分布、全量错误分布及复习阶段数量需要可靠的全量聚合。不能用分页第一页、截断候选列表或示例数填正式图表。空值和未支持统计显示“暂无数据”，真实零值显示 0。

这些口径用于开发与验收，不铺成长说明放到首页。图表只保留必要单位与简短标签。

## 视觉与交互

沿用进度后台的侧栏、学科图标和卡片分区，让两个后台有一致的整体感。保持图形占主要面积、留白清晰、文字克制；不加额外宣传文案或大段引导。

能力颜色固定为绿色已掌握、蓝色练习中、橙色待巩固、灰色尚未练，同时提供文字图例。错误图使用单一强调色；复习图用中性进展色，不将“有作答”涂成“已掌握”的绿色。

首页点击以菜单页面下钻为主，不弹出一层层题目详情。保留现有能力档案、错题记录、复习建议页面承担细节，不引入时间日历、练习时长、趋势曲线和识字矩阵。

本轮会话样稿点选学科仅突出两张对应学科图中的数据，总数字与“全科建议”图仍为全局；正式页面的菜单下钻在设计确认后实现。菜单按钮仅展示入口用途，不实现明细页。

## 本轮验收

- 首屏结构为九个学科入口和三张图，能快速看到整体分布。
- 没有题目、错因或复习建议明细，没有说明性长段落。
- 图表单位明确，练过知识点、能力状态、历史错误和复习阶段互不混淆。
- 会话样稿明确标为示例数据；布局确认后再进入聚合接口与应用开发。
